# CAP-25: visual/query hint code acceptance

Current HTTP image ingress uses visual vector candidates and optional bounded
model/title retrieval hints, then current SQL cards, full hard brief, independent
writer/review and post-copy row revalidation. It does not route image hints into
transaction authority. Retained NLU image resolution and query optimization are
retrieval hints only. Their original bodies remain dormant with legacy names.
Failed/invalid image hints now retain the actual customer caption, never invent
trending high-tech demand. Query optimizer output must be bounded single-line
customer/history vocabulary, not invented identity. Current ordinary query
rewrites retain their own independent request/constraint review boundary.

Image encoding runs bounded decode and native inference off-loop behind a
process-shared gate. Timeout/cancellation does not release a still-running
native slot; image resources and slot close in the worker's finally. Milvus has
its own native admission. Direct visual vectors now reject bool/nonfinite
values before native search. These tests use controlled models, not recognition
accuracy. HTTP visual work also has one outer40-second deadline including
retrieval, optional hint and publication. Cancellation propagates without cards.

Focused decode/native/hint/caller cases pass, including source-byte/pixel bounds,
resource-slot recovery, invalid direct vectors, caption fallback, invented query
output, current visual cancellation and deadline. Existing actual SQL direct/
visual stale stock/spec/price/removal cases remain in full regression. A focused
native timing case initially hit its existing short post-release wait once;
unchanged rerun passed. No model or provider call was used for that check.
