# Arabic per-target constraint boundary

Five actual PostgreSQL tests exercise the existing reviewed target-assignment,
staged retrieval, currentSQL hydration, Arabic capacity gate, shared model writer,
independent review and post-generation recheck together. A laptop minimumRAM
requirement and a separate chair color exclusion remain scoped to their literal
Arabic targets. WrongRAM excludes only the laptop; rejected/invented assignments
never search or persist scope; stock/spec changes during copy withhold publication
and do not persist new scope. Current writer receives each separate target trace.

This adds no model, inference stage, keyword routing, translation policy, runtime
caller, consent or mutation. Controlled extraction/review outputs prove boundary
behavior, not live multilingual interpretation or semantic review accuracy. The
broader multilingual quality gap remains open.36focused tests pass with realPG.
