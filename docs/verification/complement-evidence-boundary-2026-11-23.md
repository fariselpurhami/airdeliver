# Complement evidence boundary, REVIEW BRANCH ONLY

Observed owner-stack cart add produced face cream, blush and alternative sneakers for an apparent shoe anchor. Those are not established shoe complements. Removal produced other men's shoes, plausible alternatives, not size/style suitability proof. Synthetic demo templates have no socks/laces/shoe-care kits. Candidate transport/catalog validation passed, add semantic quality did not.

Existing bundle fallback pads weak results and cache replay does not recheck relationship. This branch adds one shared conservative catalog-asserted complement gate to cache hydration, primary selection, padding fallback, timeout fallback and final fresh-row hydration. It does not remove existing retrieval, price/activity/inventory checks or methods. Bundle cache version increments. No product data is added or changed, no provider calls or migration.

A candidate must have an explicit reviewed anchor-SKU relationship encoded in its existing string-valued attributes as `complement_for_skus`, a JSON array of exact anchor SKUs. Invalid/missing/other relations abstain. This is a catalog assertion boundary, not trusted physical-compatibility certification. Any importer capable of writing this field must be restricted to reviewed catalog data. No new database field/API write permission is introduced. Do not let customer text/model-generated metadata assert relationships without review.

No category mapping/name tokens pretend to be a learned brain. The existing retrieval remains candidate generation. Ranker/relevance evaluation and actual compatibility verification are still separate work. Current unlabeled synthetic catalog will probably return no add complements; this coverage loss is intentional and MUST be approved before merging. Returning fewer or zero products is preferable to padding unrelated stock, but this is a user-visible behavior change. It has NOT been merged/enabled on main.

Real PostgreSQL tests update committed relationship metadata independently of cached/caller objects, check revoked relations cannot replay from cache or primary/fallback, exercise timeout fallback, and retain current-price/activity/inventory tests. Existing catalog fixtures now explicitly declare their controlled phone-accessory relationships instead of silently relying on names. Pure tests reject malformed/unknown/self/name-only relation evidence. No real-model semantic accuracy is claimed.
