## How a group can close

1. Compare original useful intent against every active current caller. Mark
   dormant unreviewed implementations separately. Preserve original methods.
2. Establish success, malformed/untrusted input, owner isolation, stale/race,
   outage, timeout and cancellation at the actual relevant storage/transport.
   Evidence leads in JSON are starting points, not proof all these gates pass.
3. Record the exact tested revision, tests, result and residual limits. Decide
   whether code closure is justified independently from quality and owner state.
4. Require realistic model/source/vision/load evidence for claims that depend on
   it. Controlled output tests never earn language/entailment/vision scores.
5. Keep spending, owner deployment, held migrations and privacy-scope decisions
   under their own authority. No new live run is authorized by this document.
