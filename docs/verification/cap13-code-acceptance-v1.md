# CAP-13: finite constraint vocabulary code acceptance

Supported typed capacity is explicit RAM/memory/storage/SSD/HDD with declared
SI or IEC identity and explicit min/max markers. No SI/IEC cross-family or
implicit upgrade conversion. Active hard-brief filtering and target/setup scope
retain those existing tests. Broad query cleanup changes retrieval candidates,
never the independently reviewed hard brief or current SQL publication gates.

Other attributes are a literal contract, not a universal semantic parser:
color/material/connectors/display/features and physical dimensions may match
literal current name/category or isolated affirmative specification values.
Typographic spaces are allowed, lexical boundaries remain. No synonym,
physical-unit/locale conversion or unspecified comparison interpretation is
claimed. Unknown hard evidence withholds candidates rather than weakening a
constraint. Global shared features remain shared unless exact target assignment
is model-reviewed; current target identity cannot silently drop prior scope.
Scope input is bounded before inference and normalized duplicate targets fail.

Positive non-capacity evidence no longer comes from a flattened concatenation
of attribute labels and values. A false/unknown OLED label does not mean OLED;
separate color/material fields cannot manufacture a phrase. Negated/optional/
variant specification prose is withheld conservatively. True/yes/supported
values may bind to their own label. Original flattened permits method remains
dormant as _legacy_permits_flattened, not an active alternative. Malformed or
nonfinite stored budgets fail closed without raising through publication.
