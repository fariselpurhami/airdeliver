# CAP-29: multi-target research and source attribution code acceptance

Both active caller families are inventoried: NeuralCore staged informational
search and the retained NLU reviewed prose boundary. They pass literal targets
separately to answer_product_question; no concatenated multi-item lookup replaces
the individual source acquisitions. Existing customer-history scope and source
budget remain. Empty sources use the current scoped catalog fallback, not model
memory or global availability assertions.

Targets are now validated before any lookup or fallback. Only list/tuple literal
strings are accepted, bounded to three unique normalized identities. Whitespace
and case duplicates share one lookup; the first spelling remains canonical.
Malformed container/type/empty/oversize target sets do not silently become a
combined question. Each accepted target still gets its own bounded source lookup,
with outage, outer deadline and cancellation covered.

Coverage requires requested exact identities, no duplicate coverage entries and
at least one exact quoted fact that literally names each claimed covered target.
This additional boundary prevents even an approving controlled reviewer from
promoting a sibling with no quote attribution. Partial source evidence remains
publishable with an explicit missing-target notice; no borrowed coverage or
full-comparison claim. A legitimate pronoun-only excerpt may now be withheld;
ask for a source that explicitly names the model rather than guess the binding.
Literal occurrence is not semantic entailment. Independent exact-product and
statement review remains required; actual meaning/quality is still unverified.
