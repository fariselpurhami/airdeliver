The real Groq SDK path uses its native raw-response wrapper to inspect successful response headers and then return the same parsed result. Offline/injected adapters retain their existing create contract. Full header maps are ephemeral in process only, never persisted/logged. No external request was made during verification.

Only numeric remaining-tokens, reset durations and daily remaining-requests are used. A lower observed token remainder reduces the shared Redis admission allowance, with every subsequent estimated reservation debited. A later larger out-of-order header cannot reopen it. Values expire no earlier than60seconds or the reported token reset. Actual usage continues to reconcile original rolling reservations; unknown/failed usage stays reserved. Configured plan is never raised by headers. Request headers refer to daily requests, not RPM. Daily0imposes shared cooldown to its reported reset, conservatively24hours if absent. Retry-After/backoff/outer deadlines unchanged. This may conservatively withhold work longer than strictly necessary; it never assumes extra quota. Separate provider ITPM/OTPM/RPM/TPD limits remain externally enforced, not claimed locally modeled.

Cost estimate requires explicit exact PROVIDER_COST_MODEL and both PROVIDER_INPUT_MICRO_USD_PER_MILLION and PROVIDER_OUTPUT_MICRO_USD_PER_MILLION plus numeric input/output usage. Meter failure logs its class and does not turn an accepted reviewed answer into a fake provider failure. Header observation/lock cleanup remain safety-bearing.
